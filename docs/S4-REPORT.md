## 三、踩到的坑

### 1. B 站弹幕接口返回的是 **raw deflate**

`/x/v1/dm/list.so?oid=` 返回的不是明文 XML，也不是 gzip/zlib（没有头），
而是 **raw deflate**。用普通 utf8 解码会得到乱码，解析出 0 条。

处理：`decodeDanmakuBytes()` 依次尝试 **gzip → zlib → raw deflate → 纯文本**，
并补了单测（构造 raw deflate 数据验证）。

### 2. 标题带季标时 B 站搜不到

次元城标题是「间谍过家家 第三季」，直接拿全名搜 B 站经常 0 结果。
复用 S3 的 `titleQueryVariants` + `matchScore`：去季标、去标点、截短，再打分挑最像的番剧。

### 3. 不是所有番 B 站都有

「间谍过家家」在 B 站是港澳台/无版权，匹配到 season 后分集为 0 → 该源贡献 0 条。
这时次元城弹幕仍然正常（343 条）。**这就是多源的意义**。

## 六、S4.1 修正：B 站匹配到"预告"和"错误的季"

用户反馈：B 站明明有《间谍过家家》，我们却拿不到弹幕。

排查发现两个问题：

1. **搜索只取了前 5 条**，而《间谍过家家》B 站有 6 个 season（预告 3 集、粤配 25 集、第二季 12 集…），
   真正想要的 S1（season 41410，25 集）排在第 6 位，压根没进候选；
2. **没有"第 N 季"约束**：番剧标题不带季号时，候选「第二季」靠"集数相同 + 年份接近"赢了。

处理：
- 搜索页大小 5 → 10；
- 新增 `seasonNumber()`：解析「第 N 季 / Season N」，季号不一致扣 5 分；
- 集数不到对方一半（预告/特番）扣 4 分；
- 匹配改成**按分数排序后逐个试**，某个 season 分集为空就换下一个。

实测：次元城《间谍过家家》（2022,12 话）→ B 站 season **41410**（25 集）→ 第 1 集 cid 785726095
→ **3600 条**弹幕，加上次元城 153 条。

## 十、S4.4 修正「有资源 / 无资源」的草率语义

用户指出：原来的标记其实是「**条目来自哪个站**」——次元城=有资源、B 站=无资源，
可 B 站条目点下去会自动找源，很多都能播；将来接更多源更不成立。

改成"**这一集能不能播**"三态：

| 状态 | 判断 | 显示 |
|---|---|---|
| 可播 | 该集有播放地址（sectionId 非空） | 不显示（默认可播，不需要标） |
| 待解析 | 当前源没地址，但可自动找源 | 不显示（不断言运行时结果） |
| 不可播 | 当前源缺地址且无替代（如次元城某集没 sectionId） | 灰色「缺地址」 |

实现上不再写死"次元城=B站"，而是详情页传入 `badgeFor(episode)` 回调；
将来 S7 多源时换成 `PlaySourceRegistry`（每个 adapter 声明支持哪些集），UI 只问 registry。

### 顺带修掉的两处缓存问题

1. `AnimeEpisode.toJson` 缺 `sectionId`/`pubDate` → 已补；
2. 旧的详情缓存里没有 `pubDate`（B 站分集日期因此不显示）→ 读缓存时检测到
   「B 站分集全都没有日期」视为过期，自动重拉。

截图：`docs/assets/s4/5-episode-cards-bili.png`（B 站条目也带日期了）。


## 十一、S4.5 单实例运行 + 匹配可信度门槛

### 1. 单实例（避免 AniCh 那种 lock failed 弹窗）

AniCh 开第二个实例会弹「ThemeSettingsStorage 错误 PathAccessException: lock failed」，
本质是**两个进程抢同一个文件**。我们也一样会撞同一个 SQLite 库。

处理：`windows/runner/main.cpp` 里用**命名互斥体**做单实例：

```
CreateMutexW(nullptr, TRUE, L"Local\\anime_client_single_instance")
```

- 已有实例 → `FindWindow` 找到主窗口 → 还原/置前 → **第二个进程直接退出**（不弹错误框）；
- 实测：第二个实例 **84ms 内退出**，进程数保持 1。

> 注意：main.cpp 的注释改成英文了 —— MSVC 默认按本地代码页编译，
> 中文注释会触发 C4819 警告，而项目把警告当错误（C2220），直接编译失败。

### 2. 标题匹配加了「可信度门槛」

用户发现《学生会也有洞！》的剧集卡片配到了《学生会的一己之见》（2009/2012）的封面和日期。

原因：只按"标题包含 + 集数"打分，年份差 14 年也照样被接受。

处理：`isReliableMatch()` —— **年份差 > 2 直接否决**，分数低于 5 也不接受；
分集卡片和弹幕的 B 站匹配都走这个门槛。

实测日志：

```
[matcher] 跳过不可信匹配「学生会的一己之见」(year=2009)
[matcher] 跳过不可信匹配「学生会的一己之见 Lv.2」(year=2012)
[matcher] 跳过不可信匹配「Love Live! School Idol Project」(year=2013)
```

→ 没有可信匹配时降级为番剧封面，不再张冠李戴。

截图：`docs/assets/s4/6-match-gate.png`。


## 十二、S4.6 搜索别名扩展（"EVA 只有 4 条"）

用户反馈：搜 `EVA` 只出 4 条，但 EVA 光剧场版就好几部。

**不是匹配错，是字面搜索搜不到**。实测：

| 搜索词 | B 站 | AniList |
|---|---|---|
| `EVA` | 1 条 | **2 条** |
| `Evangelion` | — | **14 条** |
| `福音战士` | 1 条 | **0 条**（AniList 没有中文索引） |

AniList 的标题是 `Shin Seiki Evangelion` / `Evangelion Shin Movie: Jo`，
没有一条叫 "EVA"；B 站同理。

**处理**：新增 `search_aliases.dart` 别名表 + `expandSearchQuery()`：

- 原词永远排第一，最多展开到 4 个查询词（控制请求数）；
- 先查原词（含分页），再用扩展词补第一页，合并去重；
- 表里放了 25 组高确定性别名（EVA/巨人/咒术/鬼灭/无职/芙莉莲/孤独摇滚/药屋…），
  宁可少加也不加错。

**效果**（截图 `docs/assets/s4/7-search-eva.png`）：
`EVA` 从 **4 条 → 14 条**，包含 TV、旧剧场版 2 部、新剧场版 序/破/Q/终、OVA、特番。

代价：扩展词会多发 2–6 个请求（只在第一页），实测首屏仍在 1.5s 内。


## 十三、S4.7 模糊搜索（"clann" → CLANNAD）

用户反馈：名字没打全（`clann`）就一条都搜不到，希望能找到相近的番。

**处理**：用 B 站公开的搜索联想接口做兜底：

```
GET https://s.search.bilibili.com/main/suggest?term=clann&main_ver=v1
→ tag[].value: clannad / clannad第一季 / clannad第二季
```

- 只在**原词结果为 0** 时触发（不增加正常搜索的延迟）；
- 只接受"以输入开头"的建议，挡住「巨人 → 巨人网络」这类噪音；
- 最多用前 2 个建议各查一次两源，合并去重。

**效果**：`clann` → **5 条** CLANNAD 系列（TV 2007 / AFTER STORY 2008 / 两个 OVA / 剧场版）。

### 顺带修掉一个去重 bug（这条更关键）

`CLANNAD`（2007, 23 集）和 `CLANNAD ~AFTER STORY~`（2008, 23 集）被误判为同一部，
导致 **TV 版整条被吃掉**——因为旧规则里"标题包含 + 集数相同"就算重复。

修法：**包含关系只在同年才成立**。
`CLANNAD` vs `~AFTER STORY~` 年份不同 → 不合并；TV 保住了。

截图：`docs/assets/s4/8-search-fuzzy.png`。


## 十四、S4.8 继续观看去重 + 自动连播

### 1. 继续观看：一部番只留一条

原来首页会把同一部番的每一集都列出来（《学生会也有洞！》第 2 集 + 第 1 集两条），
现在按 `bangumiId` 去重，只保留**最近看的那一集**（历史本来就按时间倒序）。

### 2. 自动连播（可在设置里关）

- 设置 → 播放 → **自动连播下一集**（默认开）；
- 播放页监听 `completed`：开启且有下一集时直接切下一集，不再停在最后一帧；
- 关闭后恢复「本集播放结束」面板（重播 / 下一集 / 返回）。
