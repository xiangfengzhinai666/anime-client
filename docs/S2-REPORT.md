## 二、这层是怎么搭的

```
lib/core/network/
├─ api_client.dart      dio 封装：超时 8/15s、UA、重试（超时/5xx/429，最多 3 次退避）
│                       统一 ApiException（userMessage + retryable）
└─ images/              cover_cache.dart（接口）+ disk_image_cache.dart（LRU 落盘）

lib/features/catalog/
├─ data/
│  ├─ catalog_models.dart    AnimeSummary / AnimeDetail / AnimeEpisode / Character
│  │                         + TitleMatcher（跨源同番判定）
│  ├─ bili_wbi.dart          B 站 wbi 签名（nav 取 key → 置换表 → md5）
│  ├─ bili_catalog.dart      搜索（wbi）/ 索引 / 详情 / 分集去重
│  ├─ anilist_catalog.dart   GraphQL 搜索 / 详情 / 角色
│  └─ catalog_repository.dart 接口 + 实现（合并、缓存、AniList 补充）
├─ catalog_providers.dart    Riverpod 装配 + 首页/详情/搜索 Provider
├─ detail_page.dart          详情页（封面、简介、标签、分集、AniList 补充）
└─ widgets/                  CoverImage / AnimeCard / AnimeGrid / PagedGridView
```

### 关键设计

1. **元数据与播放源解耦**：`CatalogRepository` 只产出"档案"，S3 的播放源适配器另起一层。
2. **合并策略保守**：B 站优先；AniList 只在"标题归一化后相等/包含 + 年份差 ≤1 + 集数一致"时才视为同一部，宁可多显示一条，也不误合并。
3. **AniList 只认日文/罗马音**：中文查询在 AniList 返回 0 条（实测），所以中文一律走 B 站；B 站详情缺 `jp_title` 时，再用 B 站搜索补 `org_title` 去 AniList 匹配。
4. **分集去重按「集号」**：B 站同一季会下发内地版/中配版两份，`ep_id` 不同但集号相同 —— 按集号去重，保留先出现的正片线路。
5. **缓存两级**：详情 JSON 落 SQLite（6 小时 TTL），封面图落磁盘（LRU 200 MB）。

## 七、S2.1 修正：中文搜索的合并策略（用户反馈后重做）

**问题**：第一版按语言分流（中文只查 B 站），导致两个现实问题——
芙莉莲只有 S1（B 站没买 S2）、无职转生完全搜不到（B 站没有）。

**排查**：把 8 个中文名在 AniList 上逐个实测，**7 个能搜到**，只有「芙莉莲」返回 0。
说明"AniList 搜不了中文"是错误结论，我当初只测了一个反例就下了结论。

**新策略**（`CatalogRepositoryImpl.search`）：

```
中文/西文一律同时查 B 站 + AniList
      ↓
B 站结果自带 org_title（日文原名）→ 再查一次 AniList → 补全所有季
      ↓
CatalogMerger 合并：B 站优先；AniList 逐条与已合并结果比对，同番则丢弃
```

**去重规则**（这一版踩了两次坑才定下来）：

| 情况 | 判定 | 例子 |
|---|---|---|
| 标题归一化后完全相同 + 年份相近 | 同一部，保留 B 站 | 葬送的芙莉莲（2023） |
| 简繁一字之差（编辑距离=1） | 同一部 | 芙莉莲 vs 芙莉**蓮** |
| 相邻年份 + 集数不同 | **不同**（Part 拆分） | 无职 II（2023/13）vs II P2（2024/12） |
| 同一年 + 标题完全一致 + 集数不同 | 同一部（口径差异） | B 站 28 集 vs AniList 25 集 |
| 标题包含关系 + 集数不同 | **不同**（TV vs 剧场版） | 某番 vs 某番 剧场版 |

**结果**：

| 查询 | 修复前 | 修复后 |
|---|---|---|
| 芙莉莲 | 2 条（仅 B 站 S1 + 中配） | **7 条**（含 S2 2nd Season 2026、迷你动画、第 3 期） |
| 无职转生 | **0 条** | **3 条**（S1 2021 / S2 2023 / S2 Part2 2024） |

截图：`docs/assets/s2/2-search.png`（芙莉莲）、`docs/assets/s2/3-search-mushoku.png`（无职转生）。

**代价**：每次搜索 2–3 个请求，首屏 +400–800 ms；命中缓存后无额外开销。


## 八、S2.2 首页改版：当季新番 + 轮播（按用户反馈）

### 背景

用户指出两件事：
1. 首页「正在连载」全是柯南/海绵宝宝这类几年前的老番或长篇，不是"当季新番"；
2. 参考 AniCh 首页：**热门新番 + 中文标题**，问中文标题要不要现在做。

### 排查：谁能提供「当季 + 中文」

| 源 | 当季新番 | 中文标题 | 结论 |
|---|---|---|---|
| B 站索引 `is_finish=0` | 48 部，混着柯南/宝可梦 | ✅ | 不适合做"当季" |
| B 站搜索 | 受版权限制 | ✅ | 药屋/学生会等搜不到（0 条） |
| AniList `season` | ✅ 全 | ❌ 几乎没有中文别名 | 缺中文 |
| **次元城周表** `/api/index/weekday` | ✅ **93 部 2026 当季** | ✅ **全中文** | **选中** |

次元城（cycani）本来就是 S3 要接的播放源，现在把它的**元数据**先用起来，
既解决中文标题，又让首页条目和未来"能不能播"对齐。

### 改动

1. 新增 `CycaniCatalog`（周表 / 搜索 / 详情 / 分集），`CatalogSource` 增加 `cycani`；
2. 首页「当季新番」= 次元城周表（93 部 → 按年份/评分排序取 12），中文标题 + 「周六 23:05 更新」；
3. 首页顶部换成**轮播**：池子取 B 站"已完结 + 追番人数"，过滤超长篇与低分，按日期每天轮换 5 部，
   6 秒自动切、悬停暂停、圆点与左右箭头可点，点击进详情；
4. 原「高分推荐」行改成「热门推荐」（按追番人数），避免评分榜被柯南/小猪佩奇霸占；
5. 详情页支持 `cycani:<video_id>`：标题、英文名、评分、简介、标签、14 集分集。

| analyze | 0 issue |
| 首页 | 轮播（咒术回战 S2）+ 当季新番（无职转生 S3 / 学生会也有洞 / 乱马 1/2 等全中文） |
| 详情 | 次元城条目 14 集、简介/标签正常 |

### 说明（取舍）

- **简介是日文**：次元城的 `description` 字段就是日文，暂不翻译（S3 后可考虑用 AniList 的中文简介补）。
- **轮播"老番"的口味**：B 站"完结 + 追番人数"比"评分榜"更接近用户预期（鬼灭/咒术/间谍），
  但仍然受 B 站版权限制；后续可以把池子换成"次元城高分 + 完结"。

## 九、S2.3 首页再改：更新进度 + 老番推荐 + 同系列去重

### 改动

| 需求 | 做法 |
|---|---|
| 卡片显示"更新至第几话" | 次元城周表只有总集数，改为调 `sections` 接口的 `pager.total`（`page_size=1` 的轻请求），会话内缓存 30 分钟；卡片显示 `2026 · 更新至 13 话` |
| 热门推荐 → 日漫老番推荐 | 改成 B 站 `is_finish=1`（已完结）+ 按追番人数，两行 14 部；不再按"评分"（评分榜被柯南/小猪佩奇霸占） |
| 一屏全是同一系列 | 新增 `distinctSeries`：标题归一化后前 4 字相同视为同系列，只留第一部（鬼灭 5 条→1 条） |
| 元信息重复 | `全26话` 这类 status 已含集数时，不再额外显示"26 话" |

### 数据侧的取舍（回答"能不能照 AniCh 的数据源"）

AniCh 的"热门番剧"来自它**闭源的后端**（本质也是聚合多个站点），我们拿不到。
目前能提供的最接近数据是次元城的周表（**93 部 2026 当季，全中文**），已经用作「当季新番」；
它的排行榜接口只有 20 部且也是当季。

要更全只有一条路：**接更多站点**（S7 的多源适配器），把每个站点的"当季/热门"作为候选池合并。
这是 S7 的事，S2 阶段先用次元城 + B 站两个池子。
